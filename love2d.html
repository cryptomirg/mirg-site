A real example

This is a real session, not a mock-up: the request as it was typed, and what the agent did.

Make a LÖVE game: a breakout clone with a paddle, a ball, and three rows of bricks
  1. Checked that LÖVE was installed
  2. Wrote the game and its settings: two small files
  3. Checked the Lua for errors
  4. Started the game and read LÖVE's output, which showed none

The first message took 44 seconds.

The result. A Breakout clone: a paddle, a ball whose bounce angle depends on where it hits, three rows of bricks worth different points, three lives, and a win when the bricks are gone.

How it works with LÖVE

  • The agent writes main.lua and conf.lua, the standard layout for a LÖVE game.
  • The game opens in its own window. With macOS permission the agent can look at it and play it; without, it checks the code and the engine's output and tells you it has not seen the game.
  • LÖVE games are small and start instantly, so changes are quick to try.

What you need

  • LÖVE, free, about 15 MB. Drag it into Applications.

Mirg lists what is installed and what is missing under "See what's installed" on its home screen. If you ask for a LÖVE game without the tools for it, it tells you what to get and offers to build a web game instead.

Good to know

  • LÖVE is for 2D games.

Questions

What is LÖVE?

A free framework for making 2D games in the Lua language, also written Love2D. It is small and popular for hobby and jam games.

Do I need to know Lua?

No. You describe the game and the agent writes the Lua. The code is short and readable if you want to learn from it.

Can the agent play my LÖVE game?

Yes, once macOS has been allowed to let Mirg see and control other windows. Mirg asks for both permissions in one step.
